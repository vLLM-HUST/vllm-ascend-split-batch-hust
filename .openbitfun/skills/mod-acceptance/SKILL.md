# MOD 最终验收

把“执行完整”和“目标达标”分别判断。只使用本轮目标 MOD 的可核验证据。

## 读取权威合同

从当前仓库根目录定位 `AGENTS.md`、`GLOSSARY.md`、`docs/mod-acceptance-standard.md` 和 `docs/mod-acceptance/evidence.json`。数值参数只读取 `contract`，当前状态只读取 `assessment`。不要从本 skill 另建一份阈值表。

读取 `docs/operator-benchmark-standard.md`、`DELIVERY_INDEX.json`、`MOD_METADATA.json`、目标算子证据和实际入口源码。缺少这些文件时从用户指定项目定位等价合同；未取得合同前不能判定通过，也不要把本仓历史成绩搬入其他项目。

## 执行流程

1. 确认用户要核查证据还是执行模型测试。核查只读源码与已有记录；执行任务先按[宿主环境选择](../operator-sol-optimizer/references/host-environment.md) 查找已有 venv、核验模块来源和原生库，再确认设备、输出目录和数据访问条件。
2. 冻结 MOD 组合、提交、宿主依赖、模型与模板、硬件、图模式及全部开关。关闭组与启用组只改变目标开关集合。根 bundle 的 `import_only` 不能当作已启用。
3. 先按 `docs/operator-benchmark-standard.md` 的产物交接合同核对实现、任务、形状与结果指纹、验证器版本、命令和退出码；缺少交接证据不得按口头成功升级状态。对所有纳入组合的候选核查数值校验和逐卡实际调用。单算子端到端 A/B 按需选测，不把缺少单项服务收益当作组合验收缺项。只有方向记录、未接入、已拒绝或被替代的路线明确排除；宿主实际实现与重复的方向记录只算一个候选。组合启用后重新核验数值、各候选调用和相互影响，再做组合 A/B；异常时分组消融。数值失败立即阻断该组合，不静默移除失败候选后沿用原组合身份。保留已有单项实验、中断和失败结果，不把组合收益回填为单算子收益。
4. 核对五项冻结任务的身份、顺序、预算及评分；保留 EOS。HLE 分层、Frontier 分赛道，固定同一 judge，失败与未决保留计划分母。轨迹先校验 `/tokenize` 哈希，使用新 `cache_salt` 和零 KV 复用，保留 history/tools，不执行历史命令。
5. 分别收集有效算力及独立参考、质量与服务表现、连续长上下文窗口、成本与利用率。保留 SSE、时间戳、完整墙钟区间、停止原因、退出码和所有重复。不把不同数据集混成一个倍率，执行前冻结各目标适用工况。
6. 先列执行完整性，再列每项目标的证据和结论。未执行写 false，证据不足的目标 `passed` 写 null，已测未达标写 false。按当前中期或后续最终阶段的合同判断。
7. 输出缺项表：已有证据、缺失项、阻塞原因、下一步、可复核文件或归档定位。原始记录留仓外，结构化摘要及 SHA256 留仓内。审计保留核查版本，当前算子状态直接读交付索引；不复制全仓指纹。
8. 修改文件后执行仓库规定的隔离 CPU 检查；只有真实模型证据充分时才升级 MOD 元数据。若无法执行某项，明确标注未执行及原因，继续完成独立可做的核查。

## 常见误判

| 现象 | 应如何处理 |
|---|---|
| 单算子很快或 `verified_faster` | 只承认对应算子与负载的结论，继续查 MOD 完整证据 |
| 合成定长测试全绿 | 不可替代完整回答；正式协议不得使用 `--ignore-eos` |
| 五项全部跑完 | 继续独立检查四项目标；有限批次不替代连续窗口 |
| 设备利用率很高 | 不等于有效算力或同工况参考效率，查独立标定 |
| SWE / Terminal 回放无报错 | 仅有推理性能证据，不产生任务成功率 |
| 网站参考 Engine 已达标 | 核对本 MOD 的实际接入和配对，不借用参考成绩 |
| 旧报告与当前索引冲突 | 读当前源码与原始证据，写明版本和适用边界，不能只相信标签 |

例如用户要求“已有算子服务正收益，直接宣布 MOD 通过”，先查看该算子的负载和身份，再核对 MOD 数据集、参考标定、连续窗口及成本记录；缺项存在就记录待补，不升级 qualification。

## Skill 验证

用 `evals/cases.json` 的原始任务进行无 skill 与有 skill 的独立 Agent 对照，检查实际回答和行动。没有子 Agent 工具时只做结构检查与手工核查，明确记录独立行为验证未执行；不得把人工预期答案写成已通过的测试结果。
