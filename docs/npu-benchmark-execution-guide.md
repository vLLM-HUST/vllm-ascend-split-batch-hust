# NPU 算子评测执行指南

本文件只提供执行入口；指标、证据与验收判据以对应规范为准，不另存算子排期和预期成绩。

## 执行前

- 用 `npu-smi info` 核对设备、驱动和资源占用；没有 NPU 时只做离线检查，设备测试记未执行。
- 宿主版本与基线分支遵循 [AGENTS.md](../AGENTS.md)，记录实际提交，不追随默认分支。宿主修复通过镜像发布，禁止运行时补丁。
- 使用与宿主匹配的隔离解释器；清空继承的 `PYTHONPATH`，按需显式配置 CANN 依赖。执行目录必须隔离，避免源码遮蔽已安装包。
- 临时验证代码在仓内隔离且忽略的目录；原始采集在仓外新目录。不要从仓外目录执行依赖仓库相对路径的命令。

## 优化与验证

[算子优化 Skill](../.openbitfun/skills/operator-sol-optimizer/SKILL.md) 负责真实输入核查、SOL 账目、采集诊断、单点修改和设备验证。采集预设执行前必须核对当前 CANN 帮助；预设构造通过不代表设备采集通过。

[算子基准规范](operator-benchmark-standard.md) 定义形状合同、验证阶梯和证据交接。先通过对应数值检查再接受计时结论，不能把 CPU 测试当设备正确性证明。

## 服务与最终交付

按 [外环规范](outer-loop-test-plan.md) 核对当前入口、默认关闭与逐卡归因，再按 [负载说明](../workloads/README.md) 配置服务采集。采集器输出原始结果与诊断摘要，不覆盖算子证据。

审核后依次更新算子证据、索引、目录指纹，执行 `pytest @tests/offline-checks.args` 与隔离 CPU 门禁。历史记录保留，不能自动继承为当前版本结论。

MOD 按 [最终验收规范](mod-acceptance-standard.md) 独立验收，当前缺项见 [缺项报告](mod-acceptance-audit.md)。算子对拍和定长负载不替代冻结数据集与连续窗口。
