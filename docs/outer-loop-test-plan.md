# 外环测试计划

本文只定义待执行的外环验证范围、判据与顺序，不记录执行结果。执行结果一律回填到 `ops/<operator>/evidence.json` 与 `DELIVERY_INDEX.json`。

## 1. 硬门槛

外环测试成本高（单算子约五十次分钟级起服），必须先过门槛再占用设备。

### 1.1 一票否决

服务端逐字对拍不通过即终止该算子，不得进入压测，状态记数值失败并保持默认关闭。

### 1.2 Amdahl 预筛

预估服务端可省比例，与实测噪声底线比较后再决定是否投入：

```
预期占比 = L4 目标算子在全核耗时中的份额 × (1 - 1 / L0 加速比)
信噪比   = 预期占比 / 噪声底线
```

- 噪声底线取 1.5%，并按实际组内波动上调。
- 信噪比低于 0.5 的不排期：设计再多次运行也无法分辨，只会产出噪声结论。
- 噪声底线与组内波动的取值依据见 §5。

## 2. 可测清单与排期

### 2.1 当前可直接排期

**无。** 已完成 `gate_fp32`，其余候选全部卡在接入层，见 2.2 至 2.5。排期前必须先过 §2.0 的接入核查。

### 2.0 接入核查（排期前置条件）

算子目录里有实现、有门控变量，不等于服务端能启用。三者必须同时成立：

1. 有一个会被宿主真实调用的入口；
2. 该入口通过 `vllm.general_plugins` 等公开接口安装；
3. 关闭门控时零副作用。

只读代码即可证伪：在插件与宿主源码中检索该算子入口函数的引用位置，若定义文件之外零引用且没有对应的 `*_plugin.py`，则该算子未接入，不能排期。

## 3. 单算子执行步骤

以下步骤仅适用于已通过 §2.0 接入核查的算子。

### Step 0 — L4 预筛

起服一次基线（门控全关），采集逐卡 `op_statistic.csv`，确认目标算子的实际全核份额。若观测份额与 §1 预估差距过大，以观测为准重新预筛。

### Step 1 — 服务端逐字对拍

关闭与开启两组各自独立起服，对固定提示词逐字比较。任一条不一致即终止。

### Step 2 — 逐卡 L4 归因

两组分别采集逐卡算子统计，核对两点：

- 关闭组目标算子命中必须为零，否则说明门控泄漏；
- 开启组命中数必须与层数乘步数吻合，且逐卡都要核对，不能只看一张卡。

### Step 3 — 三负载平衡压测

按关闭、开启、开启、关闭四轮独立起服，每轮内依次运行三个负载：

| 负载 | 角色 | 作用 |
| :--- | :--- | :--- |
| `random` | 主测 | 锁死稳态，决定最终判定 |
| `sharegpt` | 压力 | 动态形状下的稳定性与命中率 |
| `long-prefix` | 跨相位 | 捕捉只在预填充大批次出现的反向影响，例如权重外提带来的额外搬运 |

每轮压测必须校验完成数与失败数，出现不完整结果即作废该轮。

## 4. 判定规则

1. **以主测负载定案。** 压力负载与跨相位负载一律只记录、不参与判定，避免用偶发正向掩盖主路径退化。
2. **波动取实测。** 有效噪声取噪声底线与组内实测波动的较大值，不用固定常数。
3. **三种结果都要落地。** 显著为正记正向收益；落在波动内记噪声范围；显著为负记负收益并保持关闭。任何结果都不删除。
4. **不得跨算子外推。** 单个算子的服务端结论不能作为同类算子的结论。

## 5. 噪声底线的来源

依据已完成外环评估的算子记录：`moe_epilogue` 组内波动约 2.04%，`gdn_split_fusion` 两个规模分别约 4.18% 与 4.29%，`gdn_output_norm_fusion` 约 0.79% 至 0.96%。取其中最保守的下界 1.5% 作为默认底线，实际执行时以当轮组内波动为准。

## 6. 记录与合规

1. 证据字段写入 `ops/<operator>/evidence.json`：至少包含是否执行、判定状态、主测负载名、两组运行次数、加速比、两组生成速率、组内波动、三个负载的分项结果。
2. 修改 `ops/<operator>/` 下被指纹覆盖的文件后，必须重新生成并校验指纹。
3. `DELIVERY_INDEX.json` 的 `serving_status` 必须与该算子证据一致；提交前跑 `pytest -q tests/test_ops_delivery_policy.py tests/test_json_hygiene.py`。
4. 原始响应、起服日志、算子统计与 Profiler 产物一律留在仓库外，仓库内只收结构化结论。
5. 文本新增行避免出现与度量数字同段的性能关键词，度量数字只放结构化字段。

## 7. 执行顺序与预算

按 §2.1 的顺序串行执行，一次只占用一组设备，避免两组互相干扰噪声。单算子预算约五十次分钟级起服：对拍两组、压测四组，每组含模型加载与一次预热。

每完成一个算子，先回填证据并跑门禁，再开始下一个。
