# 外环测试计划

本文定义算子服务验证范围与执行顺序。形状合同、数值判据和证据交接以 [算子基准规范](operator-benchmark-standard.md) 为准；MOD 最终交付按 [专门规范](mod-acceptance-standard.md)，当前缺项见 [缺项报告](mod-acceptance-audit.md)。本文件不维护第二份算子状态清单。

## 1. 测试前置条件

先核对当前实现、宿主提交、模型与形状，不从历史成绩直接排期。

- 插件实现必须通过公开插件接口可达；宿主实现必须已原生进入所测镜像。不能以文件名或是否存在 `*_plugin.py` 判断接入。
- 记录实际调用链、门控值和回退条件，确认关闭时与原生行为一致。未公开的候选维持 `gate_env=unexposed`，不能拿虚构变量起服。
- 算子数值检查通过后才接受计时；服务逐字对拍不通过立即停止压测，保留失败并保持关闭。
- 历史状态只从 `DELIVERY_INDEX.json` 和对应 `ops/<operator>/evidence.json` 查询；旧字段记录不能因格式迁移被删除。

### 核对实现方

- 在 `DELIVERY_INDEX.json` 登记实际执行的实现方。`service_route` 指向门控读者、宿主消费函数及表达式；插件路线还须有已安装的加载入口。宿主原生实现不因本仓保留 `ops/` 目录而变成插件。
- 单项和组合计划均从索引解析路线。在服务解释器内核验两棵宿主树、源码路径和指纹。任一开关无消费点、插件未获准加载或身份不匹配时不得启动该项。
- 静态合同只证明代码存在。真机上须保留同一工况的两组逐卡 L4；结构变换用形状与调用次数归因，不能仅搜同名 kernel。换宿主、插件字节或测试配置，不续用旧阶段。
- 缺路线回执的旧归档仅可按原指纹重放，不能新增服务结论。历史 L0 用的是替身实现时保留原件并标明范围，不登记为宿主复测。

## 2. 采集优先级

目标算子节省时间除以全核耗时总和，只用于选择实验优先级。全核耗时可能重叠，不是服务关键路径墙钟，不能据此判定服务收益或不可优化。`evaluate_e2e_snr_gate` 输出的是此类诊断建议。

只有测得关键路径份额，才能结合算子加速比估算 Amdahl 乐观上界。没有服务配对结果时维持待测；不能仅凭占比低写成 `within_noise`。噪声底线是实验参数，须按当轮组内波动上调，不能把默认值解释成硬件事实。

## 3. 执行步骤

使用 [负载目录与采集配置](../workloads/README.md)，复用 `tools/operator_tools/workloads.py` 的负载定义和相位选择，不另写命令副本。

1. 关闭与开启组分别独立起服，在相同提示词、种子及生成条件下逐字对拍；任一不一致即停止。
2. 核对逐卡归因：关闭组目标调用为零，开启组与层数、步数和真实调用协议一致。现有采集器仅支持文档声明的固定步数协议，不适用时不得强行套用。
3. 单算子端到端 A/B 按需选测；默认对已冻结的可用优化组合执行以下配对，未选单测不免除候选数值和逐卡归因。关闭组全部目标关闭，启用组全部目标开启，不包含仅有方向记录或不可达的实现。按关闭、开启、开启、关闭顺序独立起服；每轮完成主测、动态压力、相位交叉三个负载。解码主测为 `random`，预填充主测为 `long-prefix`，动态压力为 `sharegpt`，另一受控负载用于相位交叉检查。带行数限制的主测并发须在激活范围内，并用归因确认。
4. 每轮核对请求完成数、失败数与指标有效性；失败或不完整结果不能参与汇总。保留两组重复测量、命令和原始结果。指标采集与正式计时分开。

## 4. 判定与交接

- 主测负载判断收益方向；压力或相位交叉负载出现超出波动的退化时，阻止推荐当前配置，不能用主测正向覆盖。
- 有效噪声取配置底线与当轮组内波动较大者。记录正向、噪声范围和负向结果；这些只是所测工况的结论，不能外推到其他算子或 MOD。
- 采集器与汇总命令只产生诊断产物，不写正式证据。审核环境、形状、请求完整性、逐卡归因和全部负载后，按 [基准规范的交接顺序](operator-benchmark-standard.md#6-产物交接与离线检查) 更新证据、索引和指纹。
- 原始日志、响应和 Trace 放仓外；仓内保留结构化摘要与可校验的归档定位。缺项与历史适用性必须明确记录。

### 单算子服务 A/B 回填

从仓库根目录运行，`RUN` 指向已正常结束的仓外运行目录（含 `plan.json` 和 `completion.json`），`OP` 是交付索引中的算子名。无需 NPU。

```bash
python -m tools.operator_tools.serving_sync --run "$RUN" --operator "$OP"
```

默认只读：核对宿主身份、逐卡命中、开关顺序和请求完整性，复算各负载的吞吐与结论，并输出正式计时工况。未显式设置的服务参数不猜默认值。人工核对后，给同一命令追加 `--apply`，才更新算子证据、交付索引与目录指纹；不改默认开关，不提交或推送。重复回填同一份已同步的归档不新增历史。失败时命令返回非零，不应用不完整结果。

无 NPU 时只执行 `pytest @tests/offline-checks.args` 与隔离 CPU 门禁，服务与 MOD 测试维持未执行。设备测试串行使用独占资源；可以共用组合 profile，但必须逐项审核候选归因。组合退化或数值失败后分组排查，必要时再做单项 A/B，不默认为每个目录安排完整服务压测。
