# MOD 最终验收规范

本文件规定当前插件作为 MOD 的最终验收。算子验证仍按 [算子标准](operator-benchmark-standard.md) 执行；其结果只是 MOD 验收的前置证据。

## 1. 权威来源与版本

- 执行协议：[标准测试指南](https://vllm-hust.sage.org.ai/dataset-standard.html)及其 [standard.json](https://vllm-hust.sage.org.ai/data/dataset-standard-v1/standard.json)。
- 验收目标：[大纲对比](https://vllm-hust.sage.org.ai/b0-b1.html)中的四项目标。网页参考 Engine 的历史成绩不得转为本 MOD 的成绩。
- 本仓采用 `five-datasets-20261113-v1`。规范参数、数值门槛、来源摘要和当前缺项统一放在 [evidence.json](mod-acceptance/evidence.json)。其中 `contract` 是验收要求，`assessment` 是本仓证据核查，二者不能混读。
- 样本、顺序、来源、预算、评分、tokenizer 或统计口径改变时发布新协议或 profile；旧记录保留原身份。每次执行重新核验来源文件 SHA256。网页更新不得静默改变本仓合同。

## 2. 与算子验证衔接

| 阶段 | 必须证明什么 | 可以得出什么结论 |
|---|---|---|
| 算子阶梯 L0 | 同形状、同权重标签的纯算子对比 | 孤立算子收益 |
| 算子阶梯 L3 | 数值容差及服务贪心对拍通过 | 候选满足对应正确性护栏 |
| 算子阶梯 L4 | 逐卡实际调用、关闭组无目标调用、全核分母可核查 | 候选确实在目标执行路径生效 |
| 算子服务评测 | 主测、动态形状压力和跨相位检查，独立起服配对 | 指定算子与负载下的服务结论 |
| MOD 最终验收 | 冻结 MOD 组合，完成五数据集配对及四项目标检查 | 指定版本、模型、硬件与协议下的 MOD 结论 |

数值失败立即停止该候选的性能验收并保持 default-off。不得靠关闭失败路径、静默回退或只保留通过样本获得验收。

算子 `verified_faster` 不代表 MOD 合格；`within_noise` 不代表收益。只对纳入目标 MOD 的实现做前置核查，不要求把已拒绝或已替代的路线全部补跑。组合启用后必须重新核验正确性、调用路径和相互影响。

现有 `random`、`sharegpt`、`long-prefix` 用于算子诊断。定长强制输出、短提示对拍和旧 MMLU 冒烟不能替代冻结测试。算子标准的种子、预热与测量次数仅约束对应算子实验；MOD 执行采用冻结协议各自的参数。现有汇总器只产生算子外环结论，不得直接生成 MOD 合格标签。

## 3. 执行身份与接入条件

B0 为同一基础配置关闭目标 MOD，B1 为启用目标 MOD。冻结实际宿主提交、MOD 提交、模型权重、精度、tokenizer 与模板哈希、硬件及并行拓扑、图模式、服务参数、缓存策略和全部开关。除目标 MOD 的明确开关集合外，其余条件相同；宿主依赖必须在两组一致安装，不得混入额外优化。

当前宿主基线仍遵守 `AGENTS.md` 的分支约束，不把网站参考 Engine 的旧版本当作本仓的新基线。

执行前验证安装、公开入口、启用、关闭、实际推理与评分接口。根 bundle 的 `import_only` 只表示可发现，不能视为可运行的 MOD。若目标是根 split-batch 能力，必须先补齐宿主接缝；若目标是某个算子组合，单独冻结组合身份，不能冒称已完成根能力。

参考 Engine 一键脚本只复跑固定组合，不会自动装载任意 MOD。使用本项目实际可用的执行器；缺接口时明确记录阻塞项，不通过改显示名称伪装接入。

## 4. 固定测试范围

数量、并发、输出预算、种子和分层配额读取 `contract.datasets`，不得自行抽样或补齐请求。

| 数据集 | 检查范围 | 特殊约束 |
|---|---|---|
| MMLU-Pro | 固定子集质量与推理性能 | 既有任务及顺序不变，同时到达 |
| HLE-Verified | 固定分层子集质量与推理性能 | 文本和图像均保留，按各层单列结果 |
| FrontierScience | 固定版本全部题目的质量与推理性能 | Olympiad 与 Research 单列结果 |
| SWE-bench Pro | 公开轨迹请求的推理性能 | 只回放，不执行工具，不报告任务成功率 |
| Terminal-Bench 2.1 | 公开轨迹请求的推理性能 | 保留实际可用请求，不复制补齐，不报告任务成功率 |

两组使用完全相同的任务、请求顺序、提示内容和生成预算。保留 EOS，不得强制长度、缩短输出、按结果筛样、换题或选择性重试。失败重跑必须另立完整记录，保留原失败及未执行阶段。

HLE 与 Frontier 使用同一固定 judge；记录模型、运行时、提示、解析器、预算及替代 judge 身份。judge 流量不计入 solver 性能或成本。失败、缺失、非法答案、长度截断及未决评分保留计划分母；子集正确数不下降不等于证明总体质量等价。

轨迹保留原 history 和 tools，设置 `tool_choice=none`，不执行历史命令。两组生成前的 `/tokenize` 结果逐项匹配冻结 token ID 哈希；使用新 `cache_salt`，零 KV 复用。模型、tokenizer 或模板变化必须另立 profile。闭环并发回放不等于恢复历史到达过程。

## 5. 统计与四项目标

数值阈值只维护在 `contract.targets`，本节规定含义与证据要求。

| 目标 | 定义与必需证据 |
|---|---|
| 单芯片有效算力 | 必要有效算量 F、参与芯片数 k、无插桩且逐卡同步的区间 T；独立组件标定和依赖图推导参考时间 T_ref。对不确定分支保留上下界及证明，保守下界可用于验收。当前中期与后续最终目标分别判断。 |
| 吞吐与时延 | 同轮质量不下降；输出速率、逐请求平均 TTFT、逐请求平均 TPOT 分别达标，不得用其中一项抵消另一项。 |
| 数据集与长上下文稳定性 | 五项范围完整，质量与异常逐项可查；另外完成连续窗口并记录真实输入长度、预热、正式发起、完整排空、失败数和尾部分位数。 |
| 单位 token 成本 | 同轮质量不下降、同报价及费用范围、相同测量区间，单位成本达标且设备利用率提高；保留报价来源、全部占用资源、分摊计算和逐卡监控采样。 |

统计公式：

- `C = ΣF / (k × ΣT × 10^12)`，单位为 TFLOPS/芯片。
- `η_ref = 100 × ΣT_ref / ΣT`，参考时间必须独立标定。设备忙碌度、单算子 MFU 和相对基线速率均不得替代它。
- `Q = O / T_batch`，O 为按协议计入的已完成输出 token；T_batch 从首个请求提交到最后响应完成。禁止累加重叠请求耗时作为分母。回答错误与长度终止另列，不能因评分结果剔除已完成输出。
- TTFT 从各请求提交到首个内容 token 事件；保留原始 SSE 和时间戳。
- TPOT 为首个内容 token 到响应结束的时间除以后续输出 token 数；仅对存在后续输出的请求定义。报告排除数，逐请求等权求均值。
- 分位数对排序后的样本按 `(n-1)×q` 线性插值，报告样本数。
- `单位成本 = 10^6 × 区间分摊费用 / O`；费用必须包含同窗口全部占用资源，不把 judge 费用混入 solver。
- 设备利用率先按采样区间与测量窗口交集时长加权，再对参与芯片平均。它只描述忙碌度。
- 配对速率倍率为 `Q_candidate / Q_baseline`；改善率分别按对应基线作分母。自然回答长度不同，批次耗时倍率不等于速率倍率。重复实验逐对计算倍率后取中位数，保留全部重复。

连续窗口采用 `contract.continuous` 的参数，保留 P95/P99。有限批次分位数不能证明连续稳定性。当前来源未给出统一的尾部绝对 SLO 阈值；若要声称 SLO 达标，必须预先冻结额外阈值，不能事后编造。

每个数据集分别出结果，不把不同负载的数字混合成一个倍率。测试前冻结各目标适用的工况及聚合规则，禁止测完后挑选有利数据集宣称整体通过。

## 6. 证据交付与状态

每轮必须交付以下证据索引，原始数据在仓外保管，仓内仅保留结构化摘要、不可变定位及 SHA256：

- 协议身份、附件哈希及离线校验记录；输入任务身份、顺序和 tokenizer 核验结果。
- MOD、宿主、模型、硬件、执行器与评分身份；两组命令、环境开关差异、实际启用和回退记录。
- 逐请求响应、SSE、生成计数、停止原因、评分、失败与未执行清单；服务日志、退出码、运行起止时间。
- 各数据集质量与性能汇总、连续窗口明细、独立参考标定、费用和设备采样记录。
- 四项目标各自的结论、适用工况、计算输入和原始证据指针；声明当前中期或后续最终阶段。

发生真实测量后，`assessment.campaign_identity` 必须为对象，明确 `implementation`、`host`、`model`、`hardware`、`activation` 与 `protocol`。每项已测数据集或已判定目标的 `evidence_refs` 使用对象列表，填写仓内摘要的相对 `path` 和 `sha256`；摘要再引用仓外原件，不把任意字符串当作证据。

`assessment.execution_complete` 与 `assessment.acceptance_passed` 分开记录。未执行写 false，无法判定的目标 `passed` 写 null，并写明缺项；有完整证据证明未达标才写 false。所有目标满足对应阶段要求且执行完整后才能写 true。

算子结论继续写 `ops/<operator>/evidence.json` 和 `DELIVERY_INDEX.json`；MOD 结论写 `docs/mod-acceptance/evidence.json`，不要把总体验收字段混进算子状态。`MOD_METADATA.json` 的 qualification 与 performance_claims 只有在对应 MOD 证据充分时才能升级。
