# MOD 最终验收缺项报告

## 核查范围与结论

本报告依据 [结构化记录](mod-acceptance/evidence.json) 中 `assessment.reviewed_commit` 对应的仓库源码、交付索引和算子证据。该提交仅标识审计起点；当前状态以 `DELIVERY_INDEX.json` 和各算子证据为准，不复制全仓指纹。未启动模型服务，未恢复外部原始归档，因此“未找到”仅指本次仓库证据范围。

当前无法判定 MOD 达标。`MOD_METADATA.json` 仍为 `unqualified`，无性能主张；根 bundle 仍为 `import_only`，没有激活环境。必须先决定验收对象是根 split-batch 能力，还是已接入的算子组合，并冻结真实可执行身份。

## 最终验收缺项

| 优先级 | 缺项 | 现有依据 | 完成条件 |
|---|---|---|---|
| 先决 | MOD 组合与启停身份 | `MOD_METADATA.json`、根 manifest、`pyproject.toml` | 明确实现提交、依赖、公开入口和开关集合，证明关闭无副作用、启用实际生效 |
| 先决 | 冻结协议执行器 | `workloads/run_workload.sh` 只有算子诊断负载 | 接通任务恢复、身份校验、流式请求、评分及失败保留；不得直接沿用强制长度设置 |
| 正式 | 五数据集关闭组与启用组配对 | 未找到当前 MOD 按冻结协议执行的完整记录；历史 MMLU 冒烟参数不同 | 保存固定任务、原顺序、预算、分层评分及请求明细；轨迹只评价推理性能 |
| 正式 | 同工况参考效率 | 算子证据记录核函数时间与局部加速比 | 补必要算量、逐卡同步正式计时、独立组件标定、依赖图及参考界限证明 |
| 正式 | 同轮质量与服务表现 | 现有结果主要为合成负载；汇总器按算子速率差异判定 | 保存 SSE、完整批次时间、输出 token、停止原因和同轮评分，逐项复算目标 |
| 正式 | 连续长上下文稳定性 | 短批次及 `long-prefix` 不构成规定的连续窗口 | 两组执行各上下文窗口，记录实际长度、预热、正式发起、排空、错误及尾部分位数 |
| 正式 | 单位成本与设备利用率 | 未找到当前 MOD 同窗口的完整费用和监控记录 | 固定报价与费用范围，记录资源占用、输出量、逐卡时间加权监控与分摊计算 |
| 交付 | 完整可复核证据链 | 既有算子字段不能覆盖总体验收 | 原始记录仓外归档，仓内登记不可变定位、哈希、执行完整性和各目标结论 |

网站参考 Engine 的成绩、旧冻结组合及独立单算子收益均不能填补这些缺项。

| `gdn_conv_pack` | 已有数值、调用及服务持平记录 | 固定当前宿主身份后复核；不能因微基准收益大而声称 MOD 收益 |

| `gdn_norm_gate` | 历史微基准与容差记录；索引已登记由宿主实现替代 | 按 `gdn_output_norm_fusion` 的实际宿主路径核查，不再按旧插件重复排期 |
| `gdn_qkv_norm` | 有微基准和数值记录 | 公开注册已撤回；宿主提案无新设备验收，缺可达接缝、逐卡调用及服务配对 |
| `gdn_input_norm` | 旧字段 `l0_benchmark` 和 `l3_verification` 已有记录 | 不是“没有微基准”；缺公开入口、实际调用及服务证据，字段规范化须保留原记录 |
| `gdn_split_ba` | 有微基准与数值记录 | 有函数和环境变量，不等于服务已接线；缺调用归因与服务配对 |
| `moe_down_residual_norm`、`ffn_activation` | 有独立算子实现与历史证据 | 当前源码未注册公开入口；先补接入，再做调用与服务验证 |
| `qwen_text_split_qkv_fuse` | 数值与服务贪心对拍均失败 | 一票否决，保持关闭，修复并重新通过前置检查后才能纳入组合 |
| `moe_gate_merge`、`moe_gating_routing` | 已否定的负收益探索 | 保留记录，不作为必须补跑的正式候选 |

未公开接入的算子使用待验证标签；旧服务结果使用 `historical_only`，不能证明当前版本表现。调用可达性以源码、公开注册和当前运行证据为准。

## 下一轮执行顺序

1. 冻结验收对象，列出实际启用集合和宿主依赖；排除数值失败与已拒绝路线。
2. 解决目标集合的接入阻塞，逐项补齐算子阶梯 L3、L4 及当前版本服务诊断。已有合格证据只在身份与工况相同且原件可核验时复用。
3. 接通冻结协议执行器，先做联调；联调记录明确标为非完整验收，不能降低正式协议预算。
4. 运行全部冻结数据集配对，并单独执行参考效率、连续窗口、费用与监控采集。正式性能计时与插桩归因分开。
5. 核对执行完整性，再按预先冻结的目标工况分别判定；缺证据保留未知，不升级 MOD 元数据。

本次仅建立规范与审计，不补造模型实验。Skill 已按本仓记录手工应用核查；独立 Agent 压力场景尚未运行，场景保存在 skill 的 `evals/cases.json`。
