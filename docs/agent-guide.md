# 编程与开发规范 (Agent 与开发者通用)

本文是本仓库的最高行为准则，确保任何改动符合插件纪律，不破坏 default-off，不污染运行环境。

---

## 1. 核心硬约束

1. **两层分工与宿主基线定死**：
   - 宿主源码（`/root/host-trees/vllm-ascend` 与 `/root/host-trees/vllm-hust`）的祖先分支必须严格锁定在 **`based/image-baseline`**；
   - 任何宿主修改必须从 `based/image-baseline` 切分支，发起 PR 时 Target 必须选 `based/image-baseline`，**严禁向 `main` 切分支或提 PR**。
2. **严禁在运行树打补丁**：
   - 严禁在插件仓内编写就地修改容器运行树的动态打补丁脚本。
3. **默认关闭（default-off）**：
   - 所有算子与优化能力必须由环境变量明确门控，未启用时与原生行为严格一致、零开销、零副作用。
4. **延迟加载（Lazy Import）**：
   - 插件对外暴露必须采用惰性加载机制，包元数据发现和生命周期扫描期间严禁导入重型实现或触发 NPU 初始化。
5. **物理隔离**：
   - 原始大体积 Trace、分析数据库与外部知识库严禁提交进 Git 仓库。
6. **通俗大白话与实事求是**：
   - 汇报直击核心结论与物理实体，坚决杜绝“载波”、“领地”等隐晦暗语；
   - 负性能如实记录，严禁将算子局部耗时直接外推为端到端收益。

---

## 2. 算子开发与测试流程

1. **测试四级阶梯**：
   - 严格遵循 `L0 纯算子微基准 -> L3 数值正确性护栏 -> L4 调用链路归因 -> 服务端到端实测` 阶梯；
   - 数值失败（L3 未过）一票否决，严格保持 default-off。
2. **端到端测试硬性约束（TP=2 双卡）**：
   - 当前主基准模型为 **Qwen3.5-35B-A3B**；
   - 在 910B2 规格下必须以双卡张量并行（**TP=2**）运行；
   - 启动端到端压测前，必须运行 `npu-smi info` 检查并确认双卡均处于空闲状态。
3. **代码与测试规范**：
   - Python ≥ 3.10，遵循 ruff 格式化；
   - CPU 单元测试默认无卡可跑（`pytest -q -m "not host_tree"`）；
   - 新增算子必须在 `ops/<operator>/` 目录下建立 `README.md`、`REPORT.md` 与 `evidence.json` 三件套，并更新总索引 `DELIVERY_INDEX.json`。
