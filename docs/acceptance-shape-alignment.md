# 冻结请求范围与服务配置

先写本轮要比较的对象，再选请求范围，最后记录实际运行的服务配置。三者分别核验。[结构化对照](acceptance-shape.json)保留来源和本地采集默认值；[MOD 验收规范](mod-acceptance-standard.md)规定哪些证据可以用于验收。

## 1. 比较对象

| 要回答的问题 | 怎样配对 | 不能据此认定什么 |
|---|---|---|
| 本仓 MOD 是否有效 | 在同一宿主、模型、硬件和服务参数上，只关闭或启用目标开关。使用本仓执行器，查门控读者、真实消费点和逐卡调用。 | 安装成功、HTTP 成功或同名核出现，不等于目标实现生效。 |
| 能否复现参考 Engine | 按对应发行版冻结的工具、组合和运行配置执行。数据集入口的参考命令和引擎下载页分别有自己的版本。 | 参考引擎不是任意待测 MOD 的启用组。 |
| 课题送测是否达标 | 按[MOD 规范所引的送测方案](mod-acceptance-standard.md#3-执行身份与接入条件)比较固定基线与送测时冻结的最新候选，登记 Release、宿主提交、镜像摘要、组合及两臂实际命令。 | 整套引擎的差异不是单算子收益；旧 MOD 合同不因此改变。 |

## 2. quick / full 选请求，不选图模式

`quick` 只比较同一批固定 MMLU-Pro 题；`full` 执行项目指定的五项范围，不是五个上游数据集的全集。两组的输入、顺序、预算、EOS、评分和失败分母遵循[冻结合同](mod-acceptance/evidence.json)。题集报告质量与推理表现；公开轨迹只回放推理，不执行工具或报告解题率。快速检查、长度探针和单算子微基准都不能代替完整验收。

请求到达并发由所选协议决定。客户端参数默认值、历史 plan 契约、服务端 `max_num_seqs` 和 `max_num_batched_tokens` 分别记录。一次调度步分给某个算子的实际序列数 `N` 和 token 行数 `T` 必须从该次调用取得。并发预算不等于实际活跃数，更不等于每次调用的 `N`。

## 3. 本地采集与选题

`workloads/profile_hotspot_longrun.sh` 的默认服务参数对齐 B0 客户端参考命令；`collection_shape` 记录本轮实际请求与启动参数。参考命令不是运行回执，`FULL_DECODE_ONLY` 也不是冻结请求要求。诊断请求若只匹配长度或并发，须写明输入内容、生成预算和到达方式的差异，不能称为冻结回放。

对比热点前，核对目标宿主、权重、硬件、请求形态及每卡实际调用。最大上下文不代表实际输入长度，图配置不证明某个相位回放。各算子的服务结论只在其 `evidence.json` 登记的工况内成立。

选题、已评审计划和原始回执见[当前研发任务](optimization-next.json)。这里只规定如何比较，不另排实验。
