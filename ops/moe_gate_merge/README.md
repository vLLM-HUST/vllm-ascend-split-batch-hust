# MoE Router 与 Shared-Expert 门控合并 (`moe_gate_merge`)

## 1. 技术方案与意图
- **目标算子**：MoE 模块的两个门控投影（Router 门控 `[2048, 256]` 与 Shared Expert 门控 `[2048, 1]`）。
- **优化原理**：在 Qwen3.5 MoE 解码阶段，两路门控共享同一个经过 LayerNorm 后的激活输入。理论上可将两矩阵拼接为单一矩阵 `[2048, 257]` 执行一次合并 GEMM，意图节省一次算子启动开销。
- **状态**：**不予启用（Rejected / Negative Speedup）**，本目录作为反向结论留档。

## 2. 硬件核验现状与负性能结论
- **硬件拓扑**：Atlas 800T A2 (Ascend910B2, CANN 9.1.0)。
- **微基准实测（NPUGraph 回放）**：
  - 纯矩阵乘法层面，合并确有理论微基准加速（由两次分离 GEMM 降至合并单次 GEMM）；
  - 但合并后张量维度为 257（奇数，非 16 字节对齐）。拆分为两路连续输出时，后置切片连续化（`2x .contiguous()`）带来高额非对齐内存搬运开销；
  - 全链路完整流水线（合并 GEMM + 切片连续化）耗时增加，跑输原生两次分离 GEMM，详细数据见同目录结构化证据文件 `evidence.json`。
- **后置非连续直接消费验证**：
  - 若不做连续化，直接由 `topk` 与 `sigmoid` 消费非连续切片，后级算子受非对齐寻址影响执行时间上升，完整流水线耗时同样慢于原生基线。
