# 算子验收报告: MoE Gate 权重 FP32 外提 (`gate-fp32`)

## 1. 评测环境与形状事实
- **硬件拓扑**: Atlas 800T A2 (2×910B2, TP=2)
- **软件栈版本**: CANN 9.1.0 / vllm 0.28.1.post1.dev143+gf18cf803c / vllm-ascend 0.25.1rc2.dev125+hust (Commit `74f0c0a27`)
- **模型与权重**: Qwen3.5-35B-A3B (bf16, ND 格式)
- **张量事实**: gate.weight 形状 `[256, 2048]` (bf16) -> 预转置缓存为 `[256, 2048]` (fp32)
- **执行相位**: Decode 阶段热路径
- **调度与图模式**: cudagraph_mode=NONE / FULL / FULL_AND_PIECEWISE（各实验臂不同，以 `evidence.json` 的 `shape_facts.cudagraph_mode` 为准）

## 2. L0 纯算子对比 (Microbenchmark)
- 基线耗时 (40x Cast): 1823.11 µs
- 优化后耗时 (外提直通): 33.19 µs
- 纯算子加速比: 54.93x (单步节省约 1.79 ms 访存与小算子开销)
- **口径**: 以上为 `torch.npu.Event`、iters=1000 的 **eager 逐次下发**测量。同一 40 层链路改用 NPUGraph 打包复测为 **125.09 → 3.11 µs（40.2x）**（2026-11-14，宿主基线 `e59aaeef2`）。两套口径绝对量相差约 15 倍而比值接近，引用时必须注明口径，不得混用。

## 3. L3 数值一致性核验
- **核验标准**: 缓存的 fp32 权重与原生的 `gate.weight.to(torch.float32)` 逐位严格相等 (`torch.equal`)。
- **核验结论**: PASS (完全等价，无数值漂移)。

## 4. L4 调用链路与图归因
- **目标 Callsite**: `vllm_ascend_split_batch/gate_fp32_plugin.py` 中拦截的 `gate` 模块 forward。
- **命中验证**: 40 层（30 层 GDN 线性注意力 + 10 层全注意力，均带 MoE gate）的 gate 权重全部正确填充并被命中；开关关闭时 100% 回退原生分支。
- **整网消除核对**: 独立起服采集逐卡 `op_statistic.csv`，`Cast` 调用由 2164 次降至 1524 次，每卡减少 640 次，与 40 层乘以 16 个解码步完全吻合；两卡结果一致。

## 5. 服务端验证

- **方法**: 独立起服互斥占用设备与端口，8 条固定提示词、`temperature=0.0`、`seed=42` 逐字对拍；随后按关闭/开启/开启/关闭四轮独立起服运行受控负载与长尾压力负载。
- **逐字对拍**: 8 条全部一致，通过。
- **受控解码负载（主测）**: 判定为噪声范围内。生成速率差异与组内波动同一量级，`Cast` 的整网份额不足以在服务端稳定显形。
- **长尾对话负载（辅助，sharegpt，128 请求、并发 16、2 轮/组）**: 生成速率 **325.35 → 330.81 tok/s（+1.68%）**，逐 token 步耗时 −2.52%，组内波动 1.21% / 1.07%。该档虽越过组内波动，但按规范**不作为收益判定依据**；对外引用该 +1.68% 时必须同时给出主测 −0.16% 与 default-off 前提。
- **跨相位检查（预填充大批次）**: 权重外提会额外持有一份高精度拷贝，理论上在大批次预填充更贵，故单独设此检查。实测方向为正、未出现退化，四轮请求全部完成，同样仅记录不参与判定。
- **判定**: 以主测负载为准，记噪声范围。
